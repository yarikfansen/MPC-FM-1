# Binaural engine — исследование осуществимости (27.10.2026)

Только чтение кода, ничего не менялось и не прошивалось. Вывод одной строкой: **A (бинауральные ритмы) — реально и дёшево; B (пространственная обработка мастера) — реально в «лёгком» виде (кроссфид + ITD/ILD), полный HRTF — нет.**

## Что есть в архитектуре (проверено по коду)
- Закрытый движок отдаёт только готовый стерео-микс блоком 128 кадров, 44,1 кГц, 24 бит в `int32_t` (`sdk/include/fm1_block.h`, `fm1_engine_control.h`). Покадровых хуков по дорожкам нет.
- Оверлей уже существует: `fm1_output_mix()` ([audio_output.c:22](../app/audio_output.c)) сначала вызывает `micro_d_render(output)` (свои голоса подмешиваются в микс), затем `mfx_process(output)` (мастер-эффекты, [master_fx.c:659](../app/master_fx.c)), затем идёт гейн и сложение с USB/BT-входами. Новый звук и новая обработка встают в эту же цепочку; всё в `FM1_AUDIO_CODE` (SRAM).
- Эффекты работают во float (`l[]`, `r[]` в BSS), есть реверб, хорус, фейзер, 2x-передискретизация. Ориентир по цене: MICRO D ≈ 220 тактов/кадр (x86), ACID после облегчения ≈ 110; на устройстве пик CPU сейчас 52 % (notes.md 26.10), потолок 70 %. **Запас по пику ≈ 18 процентных пунктов** — вот весь бюджет на новое.
- Флеш: в notes.md последняя цифра образа 583 240 B (с MICRO D); RESUME называет ~216–249 KB свободно, точное число сверять сборкой `tools/fm1-build.sh`.

## A. Бинауральные ритмы / тоны мозговых волн
Два синуса f и f+Δ (Δ = 1–40 Гц: дельта 2, тета 6, альфа 10, бета 20) в левый и правый канал + необязательные «постели» (розовый/коричневый шум, дождь-фильтр шума).
- **Куда:** отдельный модуль `binaural.c`, вызов `binaural_render(output)` рядом с `micro_d_render` (до `mfx_process`, чтобы шум/ритм могли идти через реверб и EQ, либо после — как опция).
- **Цена:** 2 фазовых аккумулятора + таблица синуса 256 точек (int16, 512 B) с интерполяцией ≈ 20–30 тактов/кадр; шум (LFSR + 1-полюсный фильтр, 2 канала) ≈ 15–20; медленный вход/выход громкости (фейд) ≈ 5. **Итого ≈ 50–80 тактов/кадр — треть MICRO D, примерно +1…2 п.п. пика.** Код 2–4 KB флеша, RAM < 0,5 KB.
- **Таймер сессии** (авто-затухание через 5–60 мин) — в задаче экрана, не в аудио.
- **Качество:** 44,1 кГц с запасом (несущая 100–500 Гц). Нужна фазовая непрерывность и плавные смены Δ (без щелчков). Эффект работает **только в наушниках** (3,5 мм): динамик и сведение каналов убивают его (на встроенном динамике это просто «биения» в воздухе). Динамик выключается при подключении наушников. Bluetooth-наушники: кодек SBC/AAC сохраняет разность частот каналов, эффект работает, но **выход по BT у FM-1 в коде не проверен** (в `fm1_audio_io.h` есть только BT-вход) — не обещать. Мастер-эффекты (хорус, ring mod, моно-реверб) могут смешать каналы: тогда A подаётся после них.
- **Честная оговорка:** научные данные о пользе бинауральных ритмов для настроения/сна слабые и смешанные; продавать как «атмосферный генератор», не как лечение.

## B. Бинауральная пространственная обработка (наушники)
- **Дорожки по отдельности — нельзя**: движок отдаёт только финальный микс. Можно: (1) весь мастер-микс; (2) голоса MICRO D по одному (они наши, `render_slot`); (3) новые оверлей-источники.
- **Вариант B1 «лёгкий» (рекомендую):** кроссфид для наушников (подмешивание задержанного на 0,25–0,4 мс и срезанного 1-полюсным ФНЧ ~700 Гц-1 кГц сигнала другого канала, 2×) + ширина. ≈ 15–25 тактов/кадр, RAM ~100 B. Убирает «усталость от стерео», звук «перед головой».
- **Вариант B2 ITD+ILD-панорама:** для источника с азимутом θ — задержка ≤ 0,7 мс (≤ 31 отсчёт, дробная интерполяция) и полочный/ФНЧ-фильтр «тени головы» на дальнем ухе. ≈ 40–60 тактов на источник. Годится для 1–4 голосов MICRO D («панорама по кругу», LFO-вращение); для мастера как 2 виртуальные колонки ±30° ≈ 100 тактов/кадр.
- **Вариант B3 полный HRTF:** КИХ 32–128 отсчётов на ухо на источник: 2 колонки ×2 уха ×64 = 256 умножений/кадр + набор HRIR в флеше (по 128 B на угол на ухо ×~12 углов ≈ 3–6 KB) и своя лицензия на HRIR-данные (MIT KEMAR / CIPIC — проверить). Тактов ≈ в 4–6 раз больше MICRO D → **ломает бюджет 70 %** при работающих эффектах. Не рекомендую без измерения реального такта CPU.
- **Качество:** индивидуальность HRTF в принципе не достижима (усреднённая «голова» работает у части людей); вертикаль и «перед/сзади» слабы. **Только наушники** (на динамике — тембровая окраска, нужен отдельный выключатель/автоотключение по детекции разъёма, если её видит код — проверить `app/board`). Через BT-наушники работает как обычное стерео (если BT-выход вообще есть).
- **Реверб:** уже есть стерео-реверб в `master_fx.c`; «комната» для B = ранние отражения (3–6 линий задержки ≈ 3 KB RAM int16) — можно позже.

## UI в нашем стиле (одна страница, 4 кнопки; макет рисовать до кода)
Страница в GLOBAL-барабане (как SCOPE): строка «BINAURAL >», SAVE открывает. Верх: иконка наушников + статус.
- Режим A: K1 PRESET (DELTA/THETA/ALPHA/BETA/FOCUS), K2 BEAT Hz (0.5–40), K3 CARRIER Hz (100–500), K4 NOISE (тип + уровень).
- Режим B: K1 MODE (OFF/CROSSFEED/ROOM), K2 WIDTH, K3 AZIMUTH/ROTATE, K4 MIX.
- Внизу — таймер сессии; котик спит в A (по стилю SCOPE). Каждое значение — в `extras` (+2–6 байт).

## Риски
- CPU: тест только на устройстве (симулятор CPU не считает); мерить GLOBAL PEAK с ACID + реверб + A.
- Прошивать нельзя до дампа и теста отката (правила CLAUDE.md). Флеш: A+B1 ≈ 6–10 KB — укладываемся; экран + локализация RU добавят ещё 3–5 KB.
- Эффект проверяется только на слух в наушниках — автоматические тесты проверят лишь конечность/ограниченность сигнала (как `tests/run_master_fx.sh`).
- Конфликт мастер-эффектов (моно-фильтры) с разностью частот L/R — порядок цепочки.

## Усилия (сессий) и рекомендация
- A (генератор, шум, таймер, сохранение, хост-тест): **1 сессия**; страница UI + локализация: **0,5–1** (после согласованного макета).
- B1 кроссфид + ширина: **0,5**; B2 для MICRO D-голосов с вращением: **1**; B3 HRTF: **2+** и не обязательно.
- **Рекомендация:** делать A (+ B1 как «Headphone mode» на той же странице) — это ~2–3 сессии, +1…3 п.п. к пику, ~10 KB флеша. B3 отложить, пока на устройстве не измерены реальные такты. Первый шаг: согласовать макет страницы (без кода), потом хост-прототип звука в WAV для прослушивания в наушниках перед любой прошивкой.

## План работ (дешёвый путь, 27.10.2026)
Правила: кода нет до «да» на макет; дешёвая модель — для сборок, тестов, поиска; сильная — только DSP; на устройство — после дампа и отката.
1. **Макет** страницы BINAURAL (виджет, как SCOPE) → «да» пользователя. *(дешёвая модель + я, ~0,3 сессии)*
2. **Хост-прототип звука** (C → WAV, без прошивки): A — два синуса со сдвигом Δ, розовый шум, фейд; B1 — кроссфид. Пользователь слушает в наушниках и выбирает пресеты. *(1 сессия, DSP — сильная модель)*
3. **Модуль `app/binaural.c`** + вызов в `fm1_output_mix` рядом с `micro_d_render`; флаг `FM1_BINAURAL` в `build_config.h` (как MICRO D), чтобы собирать с ним и без. Хост-тест конечности/ограниченности. *(1 сессия)*
4. **Страница в GLOBAL** («BINAURAL >»), сохранение в extras, RU-перевод, таймер сессии, котик-«сон». *(0,5–1 сессия, дешёвая модель по утверждённому макету)*
5. **Устройство** (после дампа и отката): PEAK с ACID + реверб + A; слушать в наушниках. *(по готовности железа)*
6. **Позже, по желанию:** B2 вращение голосов MICRO D, ранние отражения; B3 HRTF — только после замера тактов.

## Идеи для дешёвой реализации
- **Синус без таблицы:** фазовый аккумулятор uint32 + парабола/полином 3-го порядка (≈10 тактов), экономит 512 Б флеша. Или общая таблица, если уже есть в движке.
- **Один аккумулятор на два уха:** левый = f, правый = f+Δ; Δ меняется только плавным сглаживанием инкремента (без щелчков).
- **Шум почти бесплатно:** LFSR + один 1-полюсный ФНЧ (розовый ≈ коричневый «на слух» достаточно); «дождь» = тот же шум через медленно качающийся фильтр. Считать шум через 1 кадр из 2 и повторять (22 кГц хватает для мягкого шума).
- **Блочный расчёт:** параметры (Δ, громкость, ширина) обновлять раз за блок 128 кадров, внутри блока — линейная интерполяция, как в `run_ladder`.
- **Целочисленно:** A и B1 полностью в int32 (без float-конверсий блока) → дешевле мастер-цепочки; если ни один мастер-эффект не включён, переиспользовать быстрый путь `run_output_int`.
- **Кроссфид B1:** задержка 11–18 отсчётов (кольцо 32 слова), один ФНЧ, коэффициент перекрёстной подмешки 0,2–0,35; «ширина» = коэффициент в mid/side (3 умножения).
- **Пресеты вместо ручной точности:** 5–6 пресетов (DELTA 2 Гц/шум-дождь, THETA 6, ALPHA 10, BETA 18, FOCUS 40 Гц + 10 Гц) занимают ≈ 50 байт; K2 только подстраивает Δ.
- **Отключать, когда не нужно:** при OFF модуль не вызывается — 0 тактов, 0 риска для пика.
- **Автоотключение B на динамике:** если код платы видит разъём наушников — включать B только с ним (проверить `app/board`), иначе показывать «HEADPHONES!».
